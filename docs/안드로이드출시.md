# 안드로이드 출시 · 광고 도입 검토

현재 앱은 **웹(PWA)** 입니다. 이 상태로 안드로이드 스토어에 올리려면 무엇이 필요한지,
광고를 붙이려면 무엇이 달라지는지 정리했습니다.

> 스토어 정책과 심사 기준은 자주 바뀝니다. 아래는 방향을 잡기 위한 정리이고,
> 실제 제출 전에는 Play Console의 최신 안내를 직접 확인해 주세요.

---

## 1. 먼저 정할 것 — 껍데기 방식

같은 웹 앱이라도 포장 방식에 따라 **할 수 있는 일이 달라집니다.** 특히 광고가 갈립니다.

| | **TWA** (Trusted Web Activity) | **Capacitor** |
|---|---|---|
| 방식 | 우리 웹사이트를 크롬으로 띄우는 얇은 껍데기 | 웹을 앱 안에 넣고 네이티브 기능을 붙임 |
| 작업량 | 적음 (반나절) | 보통 (2~4일) |
| 배포 | 웹만 고치면 앱도 즉시 바뀜 | 웹은 즉시, 네이티브 변경은 재심사 |
| 카메라 | 됨 | 됨 |
| 웹 푸시 | 됨 | FCM으로 교체 권장 |
| **AdMob** | **안 됨** | **됨** |
| 인앱 결제 | 별도 작업 필요 | 가능 |

### 결론

- **광고를 안 붙인다** → TWA. 가장 빠르고 유지비가 적습니다.
- **AdMob을 붙인다** → **Capacitor로 가야 합니다.** TWA는 사실상 크롬 창이라 네이티브 광고 SDK를 넣을 자리가 없습니다.

이 선택을 먼저 하지 않으면 나중에 갈아엎게 됩니다.

---

## 2. 공통으로 필요한 작업

### 2-1. PWA 완성도 (TWA는 필수, Capacitor도 권장)

- `manifest.json` — `name`, `short_name`, `start_url`, `display: standalone`, `theme_color`, `background_color`
- 아이콘 — **192×192, 512×512**, 그리고 **maskable** 아이콘 (안드로이드가 원형·둥근사각으로 잘라냅니다. 여백 없이 만들면 로고가 잘립니다)
- 서비스 워커 — 지금은 푸시용만 있습니다. **오프라인 기본 화면**이 있어야 설치 조건을 확실히 충족합니다
- HTTPS — Vercel이라 이미 충족

### 2-2. 도메인 연결 (TWA)

- `https://도메인/.well-known/assetlinks.json` 에 앱 서명 지문을 올려야 주소창이 사라집니다
- 안 하면 앱 안에 브라우저 주소창이 그대로 보여서 "웹사이트를 감싼 것"이 티가 납니다

### 2-3. 스토어 등록물

| 항목 | 규격 |
|---|---|
| 앱 아이콘 | 512×512 PNG |
| 피처 그래픽 | 1024×500 |
| 스크린샷 | 최소 2장 (권장 4~8장) |
| 짧은 설명 | 80자 |
| 자세한 설명 | 4,000자 |
| **개인정보처리방침 URL** | **필수** — 카메라·알림·계정을 쓰므로 반드시 필요 |

> 지금 로고 이미지(`img_a.png`)는 1MB에 가깝고 여백이 없습니다. **512×512 maskable 버전**을 따로 받아야 합니다.

### 2-4. Play Console 절차

- 개발자 계정 등록 (1회 비용)
- **개인 개발자 계정은 프로덕션 출시 전에 비공개 테스트 기간이 요구됩니다** (일정 인원 · 일정 기간). 법인 계정은 조건이 다릅니다 — **일정을 잡을 때 이걸 먼저 확인하세요.** 모르고 있으면 출시가 몇 주 밀립니다
- 데이터 보안(Data safety) 양식 — 무엇을 수집하고 어디에 쓰는지 신고
- 타깃 API 레벨 — Play가 요구하는 최신 수준을 맞춰야 함
- 앱 서명 키 관리

## 3. 주류 앱이라서 추가로 필요한 것

**이게 일반 앱과 가장 다른 지점입니다.**

- **콘텐츠 등급** — 설문에서 주류 관련 항목을 선택하면 등급이 올라갑니다. 국내 기준 **만 19세 이상**
- **연령 확인 절차** — 앱 진입 시 성인 확인이 있어야 합니다. 지금은 없습니다
- **음주 경고 문구** — 과음 경고, 미성년자 판매 금지 문구 노출
- **국가별 노출 제한** — 주류 관련 앱을 제한하는 국가가 있어 배포 국가를 골라야 합니다
- **구매 연결 문구** — 우리는 직접 판매하지 않고 판매처를 연결만 합니다. 이 점이 화면과 스토어 설명에 분명해야 오해가 없습니다

> 4장의 **로그인 · 만 19세 인증**은 스토어 출시의 선행 조건입니다. 웹으로만 운영할 때는 미룰 수 있었지만, 앱으로 내려면 먼저 해야 합니다.

## 4. 광고를 붙인다면

### 4-1. 방식 선택

| | AdMob (앱 광고) | AdSense (웹 광고) |
|---|---|---|
| 필요한 껍데기 | **Capacitor** | TWA에서도 가능 |
| 단가 | 높음 | 낮음 |
| 주류 콘텐츠 | 등급 설정 필요, 일부 광고주 제외 | 제약이 더 큼 |
| 권장 | ○ | △ |

앱으로 낼 거라면 **AdMob + Capacitor** 조합이 정석입니다.

### 4-2. 작업 목록

1. Capacitor로 껍데기 전환
2. AdMob 계정 개설 · 앱 등록 · 광고 단위(배너/전면/보상형) 생성
3. 광고 SDK 연동 및 화면별 배치
4. **개인정보처리방침에 광고 식별자 사용 명시** (필수)
5. 동의 처리 — 유럽 대상이면 별도 동의 절차가 필요합니다. 국내만 배포하면 부담이 적습니다
6. 콘텐츠 등급을 광고 설정에도 반영 (성인 대상 앱)

### 4-3. 어디에 넣을 것인가

**넣어도 되는 곳**

- 결과 화면 **맨 아래** (구매 정보·페어링을 다 본 뒤)
- 히스토리 목록 사이 (5~6개마다 하나)
- 찾기·추천 목록 하단

**넣으면 안 되는 곳**

- **카메라 화면** — 촬영을 방해하고, 오터치로 광고가 열리면 그 스캔은 버려집니다
- **분석 중 화면** — 이미 30초를 기다리는 중입니다. 여기에 광고를 넣으면 이탈합니다
- **결과 화면 상단** — 우리 서비스의 가치가 나타나는 자리입니다. 첫인상을 광고에 내주면 안 됩니다
- **전면 광고를 스캔 직후에** — 가장 흔한 실수입니다. 결과를 기다린 사용자에게 전면 광고를 띄우면 앱을 지웁니다

### 4-4. 현실적인 기대치

배너 광고 수익은 **사용자 수에 비례**합니다. 초기 사용자 규모에서는 서버비도 안 나옵니다.
반면 AI 비용은 스캔당 확정적으로 나갑니다. **광고만으로 AI 비용을 상쇄하기는 어렵습니다.**

### 4-5. 광고보다 먼저 볼 것 — 제휴 수수료

우리는 이미 **구매 링크**를 붙이고 있습니다. 여기에 제휴 프로그램을 연결하면

- 배너 광고보다 **사용자당 수익이 큽니다**
- 화면을 해치지 않습니다. 이미 있는 링크에 파라미터만 붙는 구조입니다
- 주류 콘텐츠 제약을 덜 받습니다

**광고를 붙이기 전에 제휴부터 확인하시길 권합니다.** 작업량은 훨씬 적고 효과는 더 큽니다.

---

## 5. 권장 순서

1. **로그인 · 만 19세 인증** — 스토어 출시의 선행 조건 (4장·설명서 참고)
2. **개인정보처리방침 작성** — 없으면 등록 자체가 안 됩니다
3. **PWA 완성도 보강** — maskable 아이콘, 오프라인 화면
4. **껍데기 방식 결정** — 광고 계획에 따라 TWA / Capacitor
5. **비공개 테스트** — 계정 유형에 따라 요구되는 기간을 미리 확인
6. **제휴 수수료 연결** — 광고보다 먼저
7. **광고 도입** — 사용자 수가 어느 정도 쌓인 뒤

스토어 결정과 무관하게 미리 해 둘 수 있는 일입니다.

- [ ] 512×512 **maskable** 앱 아이콘 (여백 포함)

- [ ] 스크린샷 4~8장 (촬영 → 결과 → 셀러 → 추천 흐름)
- [ ] 개인정보처리방침 초안
- [ ] 오프라인 기본 화면
- [ ] 음주 경고 · 미성년자 차단 문구
