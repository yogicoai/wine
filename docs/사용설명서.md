# 보틀 렌즈 (Bottle Lens) — 기능 설명서

> 술 라벨을 촬영하면 AI가 주종·가격·역사·페어링을 분석하고, 구매까지 연결하는 웹 앱
> 문서 작성일: 2026-07-27
>
> **웹 버전: 앱 실행 후 `/guide` 주소** (예: `http://localhost:5700/guide`) — 클라이언트에게는 배포 도메인 + `/guide`로 전달하시면 됩니다.
> 앱 안에서는 히스토리 서랍(🗂️) 상단의 "기능 설명서 보기"로도 열립니다.

## 1. 한 줄 요약

**술병 라벨을 카메라로 찍으면, AI 소믈리에가 그 술에 대한 모든 것을 알려주고 살 수 있는 곳까지 연결해 줍니다.**

12개 주종(와인·위스키·사케·전통주·맥주·브랜디·백주·데킬라·럼·진·소주·기타 증류주)을 자동 판별하며, 사전에 술 데이터베이스를 구축할 필요 없이 **세상의 거의 모든 술을 첫날부터 인식**합니다.

## 3. 화면별 사용법

### 3-1. 촬영 화면 (첫 화면)

화면 위쪽에서 **라벨 촬영 / 바코드 / 와인 리스트** 세 가지 방식 중 하나를 고릅니다.

| 방식 | 언제 쓰나 | 비용 |
|---|---|---|
| **라벨 촬영** | 기본. 병 앞면 라벨을 찍습니다 | DB에 있으면 약 3원, 없으면 약 66원 |
| **바코드** | 병 뒷면 바코드를 비춥니다. 셔터를 누를 필요 없이 자동 인식 | **0원** |
| **와인 리스트** | 식당 메뉴판을 통째로 찍습니다 | 항목 수와 무관하게 약 5원 |

- **카메라 촬영** — 가운데 셔터 버튼
- **사진 업로드** — 왼쪽 🖼️ 버튼 (갤러리에서 선택)
- **드래그 앤 드롭** — PC에서 이미지를 화면에 끌어다 놓기
- **붙여넣기** — 복사한 이미지를 `Ctrl+V`

> 카메라는 보안 정책상 `localhost` 또는 **HTTPS 주소**에서만 열립니다. 배포 후에는 정상 동작하며, 그전에는 사진 업로드로 사용하시면 됩니다.

#### 바코드에 대해

바코드는 라벨보다 정확하고 AI를 부르지 않아 **비용이 0원**입니다. 다만 "바코드 ↔ 와인" 대조표는 공개된 것이 없어 우리가 직접 쌓아야 합니다. 그래서 **쓸수록 정확해지는 구조**로 만들었습니다.

1. 이미 연결된 번호면 → 즉시 결과 (0원)
2. 판매처에서 그 번호로 상품을 찾을 수 있으면 → 이름을 얻어 DB 조회 (0원)
3. 둘 다 실패하면 → "라벨을 촬영해 주세요" 안내 후, 분석이 끝나면 **그 번호를 자동으로 연결**

즉 첫 사람은 라벨을 찍지만, 그다음부터 같은 병은 모두 공짜로 즉시 나옵니다.

#### 와인 리스트 스캔

식당에서 받은 와인 리스트를 한 장 찍으면 적힌 항목을 모두 뽑아내어

- 우리 DB와 대조하고 (사용자 평점 표시)
- 메뉴 가격을 **온라인 최저가와 견주어 배수**를 내고
- **가성비 순 / 평점 순 / 가격 순**으로 정렬합니다

와인은 통상 시중가의 2~3배가 식당 관행이라, 2배 아래면 값이 좋은 편입니다. 항목이 10개든 30개든 AI 호출은 1회이므로 원가가 늘지 않습니다.

### 3-2. 분석 중 화면

AI가 라벨을 읽고 → 주종을 판별하고 → 결과를 정리합니다. **약 30초** 걸립니다. 이미 DB에 있는 술은 **즉시** 나옵니다.

### 3-3. 결과 화면

분석 결과가 잡지 화보 형태로 정리되어 나옵니다.

| 카드 | 내용 |
|---|---|
| **히어로** | 제품명·생산자·빈티지·지역·도수, 주종 배지 |
| **인식 신뢰도** | 0~100% + "확실한 정보 / 부분 확인 / 일반 추정" 배지 |
| **사용자 평점** | 사용자들이 남긴 별점의 평균·분포 (표가 있을 때만 나타남) |
| **예상 가격** | 국내 가격대와 5단계 가격 등급 |
| **나의 셀러** | 보유 중 / 위시리스트 / 마셨어요(기록) 버튼 |
| **구매 정보** | 실제 판매처의 **상품 사진·최저가·구매 링크** |
| **빈티지별 가격** | 같은 술의 연도별 가격 비교 막대그래프 |
| **플레이버 시그니처** | 주종에 맞는 4개 축의 맛 프로필 레이더 |
| **제원** | 품종·숙성·등급 등 (맥주는 IBU·SRM 추가) |
| **음용 적기** | 언제부터~언제까지 마시면 좋은지, 피크 시점 |
| **히스토리** | 이 술의 연대기 타임라인 |
| **스토리 / 생산자** | 이 술의 이야기, 와이너리·증류소 소개 |
| **푸드 페어링** | 어울리는 음식 + **그 음식을 살 수 있는 상품 링크** |
| **평점** | Wine Enthusiast, Vivino 등 외부 평가 |
| **서빙** | 음용 온도, 서빙 방법, 숙성 정보 |
| **타이머** | 칠링 20분 / 디캔팅 60분 / 롱 디캔팅 120분 |
| **유사주 추천** | 누르면 **그 술도 바로 분석** |
| **상식 / 음용 팁** | 알아두면 좋은 이야기 |
| **이미지로 공유** | 결과를 1080×1350 카드 한 장으로 만들어 인스타·카톡에 바로 올림 |

#### 신뢰도 배지를 꼭 봐주세요

AI가 모르는 술을 지어내지 않도록, **자신이 얼마나 아는지 스스로 표시**하게 설계했습니다.

- 🏅 **확실한 정보** — 이 제품을 정확히 알고 있음
- **부분 확인** — 브랜드는 알지만 세부 정보는 불확실
- **일반 추정** — 주종의 일반적 특성으로 추정한 내용

### 3-4. 나의 셀러 (헤더 🍷 아이콘)

와인 애호가를 위한 개인 기록 공간입니다.

- **요약** — 보유 병 수 / 마신 술 / 위시리스트 개수
- **특가 알림** — 목표가에 도달했거나 최저가가 떨어진 술을 상단에 표시
- **셀러 가치** — 보유 중인 술의 **현재 최저가 합산 총액**. 시세를 아직 못 구한 병 수는 따로 밝힙니다
  - 아직 한 병도 시세를 확인하지 않았다면 금액 대신 `–` 로 표시됩니다. **0원이 아니라 확인 전**이라는 뜻입니다
  - **[시세 갱신]** 버튼을 누르면 보유·위시 항목 전체(최대 40개)를 그 자리에서 다시 조회합니다. 판매처 API는 무료라 비용은 들지 않고, 항목 수만큼 시간만 걸립니다
- **나의 취향** — 별점 기록을 분석해 *"탄닌 강한 · 바디 강한 스타일을 선호합니다"* 같은 취향 레이더 생성
- **탭** — 보유 / 위시 / 마신 술
- **항목별 기능**
  - 병 수 증감 (`− 2병 +`)
  - **목표가 설정** → 그 가격 이하로 떨어지면 알림
  - **가격 이력 그래프** — 매일 확인한 최저가를 최대 90일치 선그래프로. "관찰 이래 최저"인지 바로 보입니다. 점이 하나뿐인 첫날에는 그래프 대신 현재 최저가만 표시됩니다
  - 음용 적기 배지: **지금이 피크** / 곧 적기 마감 / 적기 지남
  - 테이스팅 노트 히스토리 (날짜·별점·향·메모)

> **가격 이력이 처음에는 비어 있는 이유**
>
> 가격 이력은 매일 도는 정기 점검이 하루 한 점씩 쌓는 값입니다. 따라서
>
> - 셀러에 **처음 담은 날**에는 시세도 그래프도 없습니다
> - **[시세 갱신]** 을 누르면 그 자리에서 현재 최저가가 채워지고, 셀러 가치 총액이 바로 계산됩니다
> - 선그래프는 **이틀째부터** 그려집니다 (점이 두 개는 있어야 선이 됩니다)
>
> 기존에 담아 두었던 술도 마찬가지입니다. [시세 갱신]을 한 번 눌러 주시면 전체가 채워집니다.

#### 자동 알림 (푸시)

셀러 화면에서 알림을 켜두면, 앱을 닫아 두어도 하루 한 번 확인해 알려드립니다.

| 알림 | 조건 |
|---|---|
| **특가** | 설정한 목표가에 도달했거나, 역대 최저가보다 5% 이상 떨어졌을 때 |
| **음용 적기** | 보유 중인 술이 피크에 들어섰을 때 / 적기가 곧 끝날 때 / 적기를 지났을 때 |

음용 적기 알림은 같은 술을 같은 이유로 **한 해에 한 번만** 보냅니다.

#### 테이스팅 노트 기록하기

결과 화면에서 **"마셨어요"** → 마신 날짜, 별점(★1~5), **느낀 향을 태그로 선택**(주종별로 다른 향 목록 제공), 메모를 남깁니다. 저장하면 보유 재고에서 1병이 자동 차감되고, 0병이 되면 '마신 술'로 옮겨집니다.

### 3-5. 히스토리 (헤더 🗂️ 아이콘)

최근 스캔한 40건의 기록입니다. 클릭하면 다시 분석하지 않고 저장된 결과를 그대로 봅니다.

## 4. 이 앱만의 차별점

1. **사전 데이터 구축이 불필요** — AI가 라벨을 직접 읽으므로 상품 DB를 미리 만들 필요가 없고, 스캔이 쌓일수록 자체 DB가 저절로 두꺼워집니다.
2. **구매까지 연결** — 정보만 주고 끝나지 않고, 실제 판매처와 최저가를 붙입니다.
3. **안주까지 판매 연결** — "스테이크와 어울립니다"에서 끝나는 다른 앱과 달리, **그 스테이크를 지금 살 수 있는 링크**를 제공합니다. 객단가를 높이는 핵심 장치입니다.
4. **정직한 AI** — 모르는 것을 지어내지 않고 신뢰도를 표시합니다.
5. **취향의 역사** — 기록이 쌓일수록 개인화된 취향 분석이 정교해집니다.
6. **와인 리스트 통째 스캔** — 식당에서 "뭘 시켜야 하나"에 답합니다. 국내 앱 중에는 거의 없는 기능입니다.

## 5. 운영에 필요한 것

`.env.local` 파일에 4개 값이 필요합니다.

| 항목 | 용도 | 발급처 |
|---|---|---|
| `ANTHROPIC_API_KEY` | AI 분석 | console.anthropic.com |
| `MONGODB_URI` | 데이터 저장 | MongoDB Atlas |
| `NAVER_CLIENT_ID` | 상품·가격 조회 | developers.naver.com (무료) |
| `NAVER_CLIENT_SECRET` | 〃 | 〃 |

**키가 없어도 동작합니다** — AI 키가 없으면 샘플 4종이 순환하는 데모 모드로 UI를 확인할 수 있고, 네이버 키가 없으면 구매 정보만 빠집니다.

#### 비용을 줄이는 방법 (효과 순)

1. **결과 캐싱** — 이미 스캔된 술은 재분석 없이 즉시 응답. **비용 0원.** 인기 술이 스캔의 대부분을 차지하므로 효과가 가장 큽니다
2. **웹 검색 기본 끄기 (권장)** — 스캔 1회 474원 → **63원, 시간도 179초 → 30초**.
   가격 정보는 이미 **네이버쇼핑 API(무료)**가 실시간으로 제공하고 있어 상당 부분 중복입니다.
   "최신 정보 더 찾기"를 사용자가 누를 때만 검색하는 방식을 권장합니다
3. **검색 횟수 축소** — 스캔당 3회 → 1~2회로 제한
4. **저비용 모델 전환** — 간단한 술은 Haiku로 처리하는 2단계 구조

- **네이버 검색**: 무료 (일 25,000회)
- **MongoDB**: 무료 티어로 초기 운영 가능

### 이미지 저장 현황 ⚠️

현재 **Cafe24(yogibo 오픈호스팅) 연동은 되어 있지 않습니다.** 코드에 FTP·외부 스토리지 연동이 없습니다.

| 이미지 | 현재 저장 위치 | 권장 |
|---|---|---|
| 스캔 썸네일 (320px) | **MongoDB에 base64로 직접 저장** | Cafe24 이미지 호스팅으로 이전 |
| 배경 이미지 | 앱 소스(`public/img/`)에 포함 | 현행 유지 가능 |

**왜 옮겨야 하나**: 이미지를 DB에 문자열로 넣으면 문서 용량이 커져 조회가 느려지고 무료 티어 용량(512MB)을 빠르게 소진합니다. 썸네일 1장이 약 20~40KB이므로 1만 건이면 200~400MB입니다.

**이전 후**: DB에는 이미지 주소(URL)만 저장되어 용량 부담이 사라지고, 이미지는 Cafe24 웹서버가 직접 서빙해 로딩도 빨라집니다.

## 8. 자주 묻는 질문

**Q. 술 정보를 미리 입력해둬야 하나요?**
아니요. AI가 라벨을 직접 읽고 웹에서 실시간 검색합니다. 등록 작업이 전혀 없습니다.

**Q. AI가 틀린 정보를 말하면요?**
모르는 것을 지어내지 않도록 설계했고, 확신도를 신뢰도 배지로 표시합니다. 가격·평점처럼 자주 바뀌는 정보는 웹 검색으로 실제 값을 확인합니다.

**Q. 웹 검색이 안 되는 계정이면요?**
자동으로 AI 자체 지식만으로 분석하도록 전환됩니다(자가 복구). 사용자는 중단 없이 결과를 받습니다.

**Q. 사진 없이 술 이름만으로도 되나요?**
됩니다. 결과 화면의 "이런 술도 좋아하실 거예요"에서 이름을 누르면 사진 없이 바로 분석합니다.

**Q. 기록은 어디에 저장되나요?**
MongoDB에 저장되어 기기를 바꿔도 유지됩니다. (현재는 사용자 구분 없이 공용 — 6-3 참고)
